# دراسة المحاور الذكية للمحتوى — NEXORA

## الخلاصة

المطلوب ليس فلترًا جديدًا، بل طبقة اكتشاف فوق الكتالوج.  
**المحور** يشرح للمستخدم ما المجموعة ولماذا يجتمع محتواها، ثم عند فتحه يعرض صفحة لها صورة جماعية وهوية وإحصاءات وفلاتر سريعة، وأسفلها بطاقات الأعمال العادية نفسها.

هذا يفصل ثلاثة أشياء لا ينبغي خلطها:

| الطبقة | الغرض | مثال |
|---|---|---|
| بطاقة العمل | عمل واحد وبياناته الحقيقية | فيلم أو مسلسل |
| الفلترة | تضييق النتائج فورًا | سنة 2024 أو الأعلى تقييمًا |
| المحور الذكي | مدخل اكتشاف قابل للمشاركة وله هوية | أفلام كرتون، دراما تركية، رعب |

العمل الواحد يمكن أن يدخل في أي عدد من المحاور دون نسخ بياناته: فيلم رسوم متحركة أمريكي عائلي يظهر في «أفلام كرتون»، و«أفلام أجنبية»، و«عائلي»، و«أفلام 2024» إن طابق قواعدها.

## تحليل الصورة المرجعية

الصورة تعرض النمط الصحيح من أربع طبقات:

1. عنوان المحور وصورة جماعية واسعة: مثال «أفلام كرتون» مع شخصيات، أو «مسلسلات تركية» مع نجوم.
2. وصف قصير يفسر المكتبة، ثم اختصارات/شرائح للتنقل داخل المحور.
3. صف بطاقات الأعمال؛ كل بطاقة تبقى بطاقة العمل الموحدة ولا تتحول إلى بطاقة محور.
4. إحصاءات أسفل منطقة المحور: عدد الأعمال، الحجم، عدد الملفات، ومتوسط/أعلى تقييم عند الحاجة.

نستعير البنية لا الأصول: كل artwork جماعي يُخزن محليًا أو يُرفع من الإدارة، ولا تجمع الواجهة وجوهًا أو ملصقات من الإنترنت عند كل زيارة.

## ما يصنف تلقائيًا من البيانات المحلية

كلها موجودة أو يمكن اشتقاقها من `media_items` و`video_files` و`categories`:

| محور | القاعدة المحلية | ينطبق على |
|---|---|---|
| أفلام كرتون | `category=kids` أو genre: `كرتون`/`عائلي`/`Animation` | أفلام، ويمكن فصل مسلسلات الكرتون |
| أفلام أجنبية | `type=movie` + tag `أجنبي` | أفلام |
| أفلام هندية/كورية/تركية/عربية | `type=movie` + وسم المنشأ | أفلام |
| مسلسلات تركية/عربية/أجنبية/كورية | `type=series` + وسم المنشأ | مسلسلات |
| أنمي | `type=anime` أو category `anime` | أنمي |
| أكشن/رعب/كوميديا/عائلي/خيال علمي | genre المخزن | كل الأنواع المناسبة |
| مختارات السنة | `release_year` أو نطاق سنوات | كل الأنواع |
| الأعلى تقييمًا | `rating >= حد` + sort rating | كل الأنواع |
| أحدث ما أضيف | `created_at` + sort newest | كل الأنواع |

وسوم المنشأ الحالية تأتي من بنية المجلد عند الفهرسة (`تركي`، `كوري`، `عربي`، `هندي`، `ياباني`، `أجنبي`) وتُدمج مع `genres`. بيانات TMDB التي حدثت سابقًا تبقى مخزنة محليًا؛ العرض لا يستدعي TMDB.

## نوعا المحاور

### 1. محاور تلقائية (Smart)

لا تحتاج أن ينشئها المدير واحدة واحدة. النظام يقرأ تعريفات ثابتة ومدروسة مثل:

```json
{
  "id": "movies-foreign",
  "scope": "movies",
  "rule": { "type": ["movie"], "tags_any": ["أجنبي"] },
  "title_ar": "أفلام أجنبية",
  "icon": "film",
  "artwork_key": "movies-foreign"
}
```

تظهر فقط إن كان عدد النتائج أعلى من حد قابل للإعداد (الافتراضي: 3 أعمال)، حتى لا نعرض محورًا فارغًا أو ضعيفًا.

### 2. محاور تحريرية مخصصة (Editorial)

هي جداول `collections` الموجودة بالفعل. يضع المدير العنوان والصورة المحلية والأولوية والقاعدة أو العناصر المختارة. تستخدم لشيء لا تستطيع القواعد العامة وصفه جيدًا مثل «أفضل ما يناسب سهرة عائلية» أو «ذكريات سبيستون».

الأولوية: التحريري أولًا عند تعارض `slug`، ثم التلقائي.

## البطاقة الموحدة للمحور

اسم مقترح: `SmartHubCard`، وهي ليست `UnifiedMediaCard`.

```text
┌─────────────────────────────┐
│ artwork جماعي محفوظ محليًا  │
│ gradient يحمي النص          │
│ [أيقونة]  أفلام كرتون       │
│ عالم مرح مناسب للعائلة      │
│  152 عمل  ·  8.9 TB          │
│                    استكشف ← │
└─────────────────────────────┘
```

- شبكة: بطاقة واحدة على الهاتف، بطاقتان على اللوحي، 3–4 على سطح المكتب.
- نسبة الصورة: `16:10`؛ لا تكون بنفس نسبة بوستر الفيلم.
- النص: عنوان عربي، والإنجليزي تحته فقط إن كان مفيدًا؛ LTR عند غياب العربية.
- الحقائق: حد أقصى اثنتان: عدد الأعمال + معلومة مفيدة (السنة/النوع/متوسط التقييم). لا تعرض حلقات مسلسل ولا تفاصيل ملفات فردية.
- الحركة: ارتفاع/إضاءة بسيطان 180–220ms، بلا فيديو ولا تبديل صور عند hover، ودعم `prefers-reduced-motion`.

## صفحة المحور عند الفتح

المسار المقترح: `#/hub/:slug`.

```text
SmartHubPage
  HeroHubBanner: artwork + icon + title + description + count + action
  QuickFacetChips: النوع، المنشأ، الجنس، السنة، الأعلى تقييمًا/الأحدث
  HubStats: أعمال | ملفات | المساحة | متوسط التقييم (إن توفرت)
  FilterToolbar: البحث والترتيب والتضييق داخل نتائج المحور فقط
  MediaCollection: بطاقات الأعمال الموحدة grid/list
```

- العنوان والصورة لا يتغيران عند الفلترة؛ فقط العداد والقائمة يتغيران.
- زر «عرض الكل» يعيد النتائج إلى القاعدة الأصلية للمحور.
- الرابط قابل للمشاركة؛ الفلاتر تكون query string مثل `#/hub/movies-animation?year=2024&sort=rating`.

## نموذج البيانات وواجهة API

لا نضع SQL أو قواعد شبيهة بـSQL في المتصفح. نضيف تعريفات محاور محفوظة وقابلة للتوسع:

```text
hub_definitions
  id, slug, source (smart|editorial), scope
  title_ar, title_en, description_ar, description_en
  artwork_path, artwork_position, accent, icon
  rule JSONB, priority, is_active, min_item_count
```

`rule` آمن ومقيد بمفاتيح معروفة فقط:

```json
{
  "types": ["movie"],
  "categories": ["kids"],
  "tags_any": ["كرتون", "عائلي"],
  "year_from": 2020,
  "rating_gte": 7
}
```

الـAPI:

| Endpoint | الناتج |
|---|---|
| `GET /api/hubs?scope=movies` | بطاقات المحاور مع العدد وartwork المحلي |
| `GET /api/hubs/:slug` | تعريف المحور وملخصه وإحصاءاته |
| `GET /api/hubs/:slug/media?...` | أعمال المحور، مع pagination والفلترة والترتيب |
| `POST /api/admin/hubs/rebuild` | يعيد حساب counts/cache بعد الفهرسة أو تغيير قواعد (اختياري) |

حساب العدد والنتائج يتم في PostgreSQL عبر نفس قاعدة `ListMediaItems`، مع فهارس على `type` و`release_year` و`rating` وGIN لـ`genres`. لا يجلب المتصفح 1000 عمل ثم يصنفها في JavaScript.

## الصور الجماعية

`artwork_key` لا يعني «ولّد الصورة الآن». التسلسل الصحيح:

1. لكل محور smart صورة افتراضية محلية عامة في `assets/hubs/<slug>.webp`.
2. يمكن للإدارة استبدالها بصورة مرفوعة/مسار محلي؛ هذا يغلب الافتراضي.
3. لا توجد صورة؟ نستخدم backdrop محليًا من أعلى عمل في المحور مع gradient، لا collage عشوائيًا.
4. لا نستعمل أي صور TMDB غير مخزنة محليًا.

- [ ] إضافة artwork جماعية ثابتة ومخصّصة لكل محور من لوحة الإدارة عند توفر الأصول المرخصة أو المُنشأة محليًا.

## خطة التنفيذ الآمنة والأداء

1. توحيد قاموس وسوم النوع/المنشأ، والتأكد من حفظه عند الفهرسة والتحديث اليدوي.
2. إضافة `hub_definitions` وseed لمحاور عالمية، مع artwork محلي placeholder وقيود JSON للقاعدة.
3. API PostgreSQL للمحاور ونتائجها، مع pagination؛ اختبار القواعد وأولوية التحريري.
4. `SmartHubCard` و`SmartHubRail` واستبدال `HubBannerCard` الثابت في الأقسام تدريجيًا.
5. `SmartHubPage` مع Hero خاص بالمحور و`MediaCollection` و`FilterToolbar` الموجودين.
6. تحديث لوحة الإدارة: تفعيل/إخفاء، تغيير ترتيب وصورة وعنوان وقاعدة؛ لا يلزم أن ينشئ المدير المحاور الأساسية يدويًا.
7. اختبار مكتبة كبيرة: استعلامات DB فقط، lazy-loading للصور تحت الطية، cache قصير للـcounts، وعرض skeleton ثابت الحجم.

## قرارات لا نتنازل عنها

- لا يختفي أو يتغير أي عمل من قائمة القسم الأصلية بسبب المحاور.
- المحور لا ينسخ الأعمال ولا ينقلها؛ هو تعريف استعلام وإطار عرض فقط.
- لا نستخدم عدد حلقات المسلسل في بطاقة المحور أو بطاقة المسلسل العامة.
- كل نتيجة وصورة معروضة تأتي من التخزين المحلي أو قاعدة البيانات.
- لوحة الإدارة تضبط العرض والهوية؛ اكتشاف المحتوى الأساسي يبقى تلقائيًا.
