تأكدت. api.next وapi.cache لا وجود لهما في NEXORA إطلاقًا — ليستا من هذا المشروع. إليك الشرح المختصر.

ما تشغّله فعليًا في NEXORA
هناك برنامج Go واحد فقط للخادم

├── server/cmd/
│   ├── api/               ← ⭐ هذا هو "الـ API" — خادم الإنتاج
│   ├── copybridge/        ← خدمة نسخ USB (اختيارية)

server = المجلد الذي يحتوي كل شيء. api = البرنامج الوحيد من نوعه.

فـ"server" و"api" ليسا خادمين مختلفين — "api" هو الخادم، و"server" هو مجلده. عندما تقرأ cd server; go run ./cmd/api فهذا يعني: ادخل مجلد server ثم شغّل برنامج api الذي داخله.

أما api.next وapi.cache
لا وجود لهما في NEXORA. بحثت في كل الملفات والإعدادات — صفر نتيجة.

هذان الاسمان من إطار Next.js (مشروع JavaScript/TypeScript آخر):

الاسم	من أين	ما هو
api.next	Next.js	ناتج البناء (.next) — مجلد مؤقت
api.cache	Next.js / Vercel	مجلد cache للبناء
api	NEXORA ✅	خادم Go الحقي
server	NEXORA ✅	مجلد يضم الخادم
NEXORA مكتوب بـ Go + React، لا يستخدم Next.js إطلاقًا. فلا حاجة لهذين الاسمان.

9.6 مصادقة الـ Bridge (ADR-011)
