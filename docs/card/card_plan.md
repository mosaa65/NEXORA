# نظام بطاقات NEXORA الموحد

> الحالة: منفّذ للكتالوج والصفوف الرئيسية. المصدر التشغيلي للبطاقة هو قاعدة بيانات NEXORA فقط.

## قاعدة البيانات أولاً

لا تتصل بطاقة العميل بـTMDB، ولا يستخدم المتصفح مفتاح TMDB. يقتصر TMDB على عملية التحديث اليدوي أو عامل التحديث في الخادم:

```text
TMDB (فقط عند التحديث) → الخادم → PostgreSQL + الصور حسب إعداد الإدارة → API المحلي → UnifiedMediaCard
```

- كل نص أو رقم معروض يصل إلى العميل من `/api/media` وقاعدة PostgreSQL.
- تستمر المكتبة والبطاقات بالعمل من دون إنترنت؛ عدم توفر TMDB لا يمنع التصفح.
- الصور تظل وفق تفضيل الإدارة: مسار محلي عند `local`/`hybrid`، أو رابط الصور المخزن عند `remote`. البطاقة لا تستدعي TMDB API في الحالتين.
- عند التحديث، تحفظ حالة TMDB محلياً في `media_items.status` وتُحفظ التفاصيل الخام قصيرة العمر في `metadata_snapshots`.

## عقد ملخص البطاقة

الحقول التالية تأتي من قاعدة البيانات في كل عنصر من `/api/media`:

```json
{
  "status": "completed",
  "season_count": 3,
  "tmdb_season_count": 4,
  "tmdb_episode_count": 52,
  "file_count": 42,
  "total_size": 67894567890,
  "best_resolution": "4K",
  "runtime_minutes": 134,
  "has_arabic_audio": true,
  "has_arabic_subtitles": true
}
```

- `total_size` و`best_resolution` والصوت والترجمة: محسوبة من `video_files` فقط.
- `season_count`: محسوب من `seasons`.
- `tmdb_season_count` و`tmdb_episode_count`: أرقام TMDB المحفوظة محلياً في `metadata_facets`. لا تُستبدل بأرقام ملفات المكتبة؛ تعرض البطاقة الفرق بين المتاح محلياً وإجمالي المنصة عند وجوده.
- `runtime_minutes`: مدة TMDB المحفوظة في `metadata_facets` للفيلم، ثم مدة الملف المحلي كبديل.
- `status`: قيمة NEXORA مستقرة: `completed` أو `ongoing` أو `cancelled` أو `upcoming`.

---

الدراسة خلصت، والصورة واضحة: عندكم أساس ممتاز لمكوّن موحّد اسمه `UnifiedMediaCard` مستخدم فعلاً في الرئيسية وصفحات الأقسام؛ إعادة بنائه ستنعكس على معظم النظام من ملف واحد.

الأهم: البطاقة يجب أن تعرض «هوية العمل + ما هو متاح محلياً»، لا أن تخلط بيانات TMDB مع معلومات الملفات.

| العنصر | المصدر | يظهر في البطاقة؟ |
|---|---|---|
| الاسم العربي والإنجليزي | `media_items` / TMDB | نعم، العربي أولاً وتحته الإنجليزي إن اختلف |
| سنة الإصدار | TMDB/قاعدة البيانات | نعم |
| تقييم TMDB | TMDB/قاعدة البيانات | نعم، فقط عند توفر قيمة حقيقية |
| النوع: فيلم/مسلسل/أنمي… | قاعدة البيانات | نعم |
| مكتمل / مستمر / ملغي… | TMDB ثم `media_items.status` | نعم، بشارة حالة واضحة |
| التصنيفات | TMDB/قاعدة البيانات | اختيارياً: تصنيف واحد أو اثنان في المقاسات الكبيرة |
| عدد المواسم | جدول `seasons` أو TMDB | للمسلسل والأنمي فقط |
| الحلقات المتاحة محلياً | `video_files` | للمسلسل والأنمي فقط |
| حجم المحتوى | `SUM(video_files.file_size)` | نعم، حجم العمل؛ وعند بطاقة موسم: حجم الموسم فقط |
| المدة | ملف الفيلم أو TMDB | للفيلم فقط؛ لا تظهر كمدة إجمالية للمسلسل |
| الجودة | `video_files.resolution` | نعم، أفضل جودة محلية مثل 4K / 1080p |
| صوت/ترجمة عربية | `audio_tracks` و`subtitles` المحلية | رمز موجز عند توفرها، وليس من TMDB |

قرار التصميم المقترح:

- بوستر سينمائي بنسبة 2:3، مع طبقات تدرّج هادئة تحفظ وضوح النص.
- أعلى البطاقة: شارة النوع يميناً، والتقييم الحقيقي يساراً.
- أسفل البوستر مباشرة: العنوان العربي بسطرين كحد أقصى، وتحته العنوان الإنجليزي بخط أصغر إذا كان مختلفاً.
- سطر معلومات ذكي واحد فقط، يتغير وفق النوع:
  - الفيلم: `2024 · 2س 14د · 4K · 18.6 GB`
  - المسلسل/الأنمي: `3 مواسم · 42 حلقة متاحة · 63.2 GB`
  - الموسم: `الموسم 2 · 12 حلقة · 14.8 GB`
- شارة الحالة: `مكتمل` أخضر، `يعرض الآن` بنفسجي/وردي، `قادم` أزرق، `ملغي` رمادي. لا نعتمد على اللون وحده؛ النص ظاهر دائماً.
- إن لم تتوفر البيانات لا نختلق أرقاماً: لا `1080p` افتراضية ولا تقييم `8.5` افتراضي. هذا موجود حالياً في التحويل داخل صفحات العرض ويجب إزالته عند التنفيذ.

بالنسبة للـhover: أتفق تماماً، زر تشغيل كبير في منتصف البوستر يحوّل البطاقة إلى واجهة مشغل ويكسر فخامتها. البديل الأفضل:

- ارتفاع خفيف جداً للبطاقة مع ظل/إضاءة محيطية من ألوان البوستر.
- ظهور طبقة معلومات صغيرة في الأسفل: الحالة + الحجم + زر سهم رقيق بعنوان «التفاصيل».
- الضغط في أي مكان يفتح التفاصيل؛ التشغيل يبقى داخل صفحة التفاصيل فقط.
- على الجوال لا نعتمد على hover، فالبطاقة تبقى مكتملة وواضحة دون أي تفاعل خفي.

تخصيص المحتوى حسب النوع سيكون منطقياً داخل نفس المكوّن، وليس عبر بطاقات منفصلة:

```text
UnifiedMediaCard
  ├─ media: بيانات العمل المشتركة
  ├─ context: catalog | carousel | season
  └─ variant: standard | compact
```

وهو يقرر تلقائياً:

```text
فيلم     → سنة + مدة + جودة + حجم
مسلسل    → مواسم + حلقات محلية + جودة + حجم إجمالي
أنمي     → مواسم/أجزاء + حلقات محلية + جودة + حجم إجمالي
موسم     → رقم/اسم الموسم + حلقات الموسم + جودة + حجم الموسم
```

من مراجعة قاعدة البيانات: المعلومات الخام اللازمة موجودة أو ممكنة بسهولة:

- `media_items`: العناوين، السنة، التقييم، النوع، الحالة، البوستر، التصنيفات.
- `seasons`: رقم وعنوان الموسم.
- `video_files`: الحجم، المدة، الدقة، الصوت، الترجمات، والحلقات.
- لقطات TMDB: تفاصيل إضافية للموسم والحلقة والحالة والترجمات.

لكن واجهة قائمة المحتوى الحالية ترجع فقط معلومات مختصرة؛ لا ترجع `status`، ولا الحجم المجمع، ولا عدد المواسم، ولا أفضل جودة فعلية. لذلك خطوة التنفيذ الصحيحة لاحقاً هي إضافة “ملخص بطاقة” محسوب من الخادم ضمن نفس نتيجة `/api/media`، مثل:

```json
{
  "status": "ended",
  "season_count": 3,
  "episode_count": 42,
  "total_size": 67894567890,
  "best_resolution": "4K",
  "has_arabic_audio": true,
  "has_arabic_subtitles": true,
  "runtime_minutes": 134
}
```

وهذا أفضل من تحميل تفاصيل كل عمل على حدة، ويحافظ على سرعة صفوف الرئيسية والبحث.

بيانات TMDB التي تخدم البطاقة مباشرة:

- للفيلم: `title`, `original_title`, `release_date`, `runtime`, `status`, `vote_average`, `genres`, `poster_path`.
- للمسلسل/الأنمي: `name`, `original_name`, `first_air_date`, `status`, `number_of_seasons`, `number_of_episodes`, `vote_average`, `genres`, `poster_path`.
- للموسم: `season_number`, `name`, `air_date`, `episode_count`, `poster_path`.
- بيانات الحجم والجودة والصوت والترجمات ليست من TMDB؛ مصدرها المحلي فقط.

لاحظت أيضاً أن كود العرض الحالي يضع أرقاماً تجريبية عندما لا توجد بيانات، مثل سنة 2024 وتقييم 8.5 وجودة 1080p. هذه أول نقطة سأصححها عند بدء التنفيذ حتى تبقى البطاقة صادقة وفخمة في آن واحد.
