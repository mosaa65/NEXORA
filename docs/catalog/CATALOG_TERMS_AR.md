# قاموس NEXORA المبسّط: ما الذي يخزّنه النظام؟

هذا الدليل يشرح الكلمات التي تظهر في الكود ولوحة التحكم بلغة بسيطة. الفكرة الأهم: **ملف الفيديو ملك للمكتبة، أما البيانات الوصفية فهي بطاقة تعريفه**. تحديث الثانية لا يحذف أو يبدل الأولى.

| المصطلح | معناه ببساطة | مثال | أين يُحفظ؟ |
|---|---|---|---|
| العمل (`media item`) | صفحة فيلم أو مسلسل أو أنمي واحدة في NEXORA | فيلم *Spider-Man: No Way Home* | `media_items` |
| ملف الفيديو (`video file`) | الملف الحقيقي على القرص، وقد يكون للفيلم أكثر من نسخة | `D:\Movies\Spider-Man...mkv` | `video_files` |
| Metadata / بيانات وصفية | معلومات تعريفية وليست الفيديو نفسه: الاسم، القصة، السنة، التقييم، الأنواع، الملصق | سنة 2021، أكشن/مغامرة، تقييم 8.2 | أعمدة `media_items` + لقطات خام |
| TMDB | مصدر خارجي للمعلومات، يستخدم فقط عندما يطلب المدير إثراء أو تحديث عمل | جلب اسم الفيلم وصورته | لا يُستدعى عند التصفح |
| لقطة (`metadata snapshot`) | نسخة JSON كاملة مما أعاده TMDB، نحتفظ بها محلياً للاستفادة لاحقاً | وثيقة الفيلم بالعربية أو الإنجليزية | `metadata_snapshots` |
| مزود (`provider`) | اسم الجهة التي جاءت منها البيانات | `tmdb` أو `mal` | مع السجل واللقطة |
| المعرف الخارجي (`external_id`) | رقم ثابت لدى المزود، وهو الهوية الحقيقية للربط—not الاسم | رقم فيلم TMDB أو رقم شخص | `metadata_external_id` أو جداول الكتالوج |
| سلسلة/فرنشايز (`provider collection`) | مجموعة أفلام رسمية يربطها TMDB بمعرف واحد | Spider-Man (MCU) Collection | `provider_collections` |
| تجميعة تحريرية (`collections`) | مجموعة يصممها مدير NEXORA بنفسه، وليست سلسلة TMDB | «أفلام ليلة الجمعة» | `collections` و`collection_items` |
| رابط سلسلة | يقول إن هذا الفيلم عضو في تلك السلسلة | الفيلم جزء من سلسلة Spider-Man | `media_collection_links` |
| شخص (`person`) | إنسان حقيقي: ممثل أو مخرج أو كاتب | Tom Hardy | `people` |
| اعتماد (`credit`) | علاقة الشخص بعمل محدد ودوره فيه | ممثل شخصية/مخرج الفيلم | `media_credits` |
| شخصية خيالية | الدور داخل عمل، مثل Spider-Man؛ ليست شخصاً حقيقياً | Peter Parker | حالياً نص داخل `media_credits.character_name` |
| فهرسة (`indexing`) | قراءة ملفات المجلد وإدخالها إلى قاعدة البيانات، بلا حاجة للإنترنت | اكتشاف فيلم جديد على D: | scanner → `media_items` / `video_files` |
| إثراء (`enrich`) | جلب بيانات العمل من TMDB وحفظها محلياً | إضافة القصة والصور والسلسلة والطاقم | إجراء إداري صريح |
| ذاكرة مؤقتة/كاش (`cache`) | بيانات وصور محفوظة محلياً كي يقرأها النظام سريعاً ودون شبكة | بوستر في `assets/images` | PostgreSQL + القرص |
| `image_mode` | سياسة الصور: محلي بالكامل، هجين، أو رابط خارجي | local يحفظ الصورة، remote لا ينزلها | إعدادات TMDB |

## كيف تتحرك البيانات؟

```text
ملف على القرص
  → فهرسة: ينشأ العمل وملفه محلياً
  → إثراء اختياري: TMDB يرسل البيانات
  → NEXORA يحفظ النصوص واللقطات والصور المسموح بها محلياً
  → يستخرج السلسلة والأشخاص والاعتمادات
  → المتصفح يقرأ من NEXORA / PostgreSQL فقط، حتى لو انقطع الإنترنت
```

## أمثلة على أرقامك الحالية

- قد تظهر سلسلة Spider-Man حتى لو كان جزء واحد فقط متاحاً في مكتبتك؛ بينما `parts_count = 4` يعني أن TMDB يعرف أربعة أجزاء رسمية في السلسلة ككل. تعرض الصفحة الأجزاء غير الموجودة على أنها «قيد الإضافة» مع بياناتها المحفوظة محلياً.
- ظهور Tom Hardy بعملين لا يعني أن NEXORA جلب كل أفلامه من الإنترنت؛ يعني فقط أن له عملين موجودين في مكتبتك ومربوطين محلياً.
- إذا ظهرت صورة شخص، فهي محفوظة في مجلد صور NEXORA. إن لم تحفظ الصورة محلياً يظهر التصميم البديل بدلاً من تنزيلها أثناء التصفح.

## الفرق الذي يمنع الخلط

لا نربط بالاسم أبداً. اسم السلسلة أو الشخص قد يُترجم أو يتغير أو يتكرر؛ أما `provider + external_id` فهو ثابت. لذلك إعادة الإثراء لا تنشئ سلسلة أو شخصاً مكرراً حتى لو تغير العنوان العربي.
